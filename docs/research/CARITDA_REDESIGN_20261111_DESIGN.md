# CARITDA 재설계: 화면 설계와 A/B 디자인

2026-11-11 · 기준 main 80f76b1 · 제안이며 실제 앱 적용 아님. CARITDA는 상표 검증 전 가칭.

## 1. 제품 정의와 결정

**내 차의 확인할 일을 알아보고, 문제를 남기고, 다음 운전자에게 잇는 서비스.**
차량 건강·AI 문제 분석·문제 기록/인계의 세 영역을 유지한다. AI는 저장된 문제에 맥락적으로 붙이고 전역 채팅 메뉴는 만들지 않는다. DriveCheck의 위치·길 안내·보조 기능은 차량 건강의 하위 영역이며 홈의 주역이 아니다. Gleo는 향후 승인된 버튼 없는 호출을 목표로 하고 독립 큰 메뉴/캐릭터/호출 버튼을 신설하지 않는다.

기존 연구와 달리 '현재 차량 수치 두 카드와 기존 홈 구조 유지'를 전제로 하지 않는다. 다만 **앱 홈 자체는 필요하고 유지**한다. 사용자의 요구는 홈 제거가 아니라 과밀한 전역 탐색과 반복 버튼 제거다. 기존 안전·초안·작성자·수동 상태 의미는 시각 디자인과 무관한 불변 계약이다.

## 2. 새 탐색 구조

- 홈 상단: CARITDA 워드마크(버튼 아님), **설정·도움말 1개**. 현재 화면에 홈 버튼을 중복 표시하지 않는다.
- 하위 화면 상단: **이전 / 화면 제목 / 홈**. 최대 2개 탐색 버튼, 기록·차량·메뉴 탭 없음. 이전은 실제 출발 화면·필터·스크롤, 홈은 앱 첫 화면이다. OS HOME intent를 쓰지 않는다.
- 운전자: 홈 본문의 '기록 운전자 · 이름 / 변경'을 유지한다. 설정에도 관리 진입을 두되 홈은 빠른 전환, 설정은 이름/보관 관리 목적이다. 두 경로가 필요한 작업 맥락이므로 무조건 중복 삭제하지 않는다.
- 어디서든 기록 전역 탭을 없애면 건강→기록은 홈 경유 2탭이다. 이 비용을 명시적으로 수용한다. 실제 과제에서 빈번한 왕복이 확인될 때만 해당 화면의 '이 정보로 문제 남기기' 같은 맥락 행동을 추가한다.
- 하위에서 설정은 홈→설정 2탭. 설정/도움말 자체에서 기능 전체 링크를 다시 나열하지 않는다.
- 이동은 captureDraft 성공 뒤에만 실행한다. 실패는 화면에 남고 '작성 내용을 보관하지 못했어요. 다시 시도해 주세요.'를 표시한다. 목록/상세/도움말/AI Activity 왕복에도 원래 상태를 복원한다.

## 3. 홈의 정보 우선순위

1. **기록 운전자 확인**: 미확정일 때 쓰기 행동 전 운전 시작 확인. 선택 후보만으로 기록 주체를 바꾸지 않는다.
2. **지금 확인할 내용**: 다른 운전자 미확인 문제 → 운전자가 관리 중인 미점검 문제 → 근거가 있는 차량 변화 → 새 문제 기록 제안. 순서는 서비스 우선순위이지 긴급 안전 진단 우선순위가 아니다.
3. **문제 남기기**: 항상 접근 가능. 우선 카드가 이미 같은 행동을 제공하면 별도 복제 CTA는 생략한다.
4. **차량 건강 요약**: 지원된 값·단위·최신 시도/성공·오래됨. 문제 전체를 정상/주의로 합산한 건강 점수는 만들지 않는다.
5. **기록·인계**: 저장 기록을 찾는 한 경로. 미확인 인계 CTA는 미확인 조건의 큐로, 전체 보기는 모든 기록으로 가므로 목적이 다르다.

와이드: 왼쪽 7/12 우선 행동+작성, 오른쪽 5/12 차량 요약+기록 허브. 좁은 창/큰 글자는 위 순서 그대로 한 열. 가장 큰 카드 하나가 가장 중요한 행동을 말한다. 자동 팝업·자동 회전·가로 캐러셀 금지.

## 4. 화면별 상세 설계도

### S01 홈
필수: 현재 기록 운전자, 위 우선 카드, 기록 시작, 일부 차량 데이터 요약과 신선도, 전체 기록 진입. 상단은 설정·도움말만. 카드 전체 클릭과 내부 동일 버튼을 이중 포커스로 만들지 않는다. CTA가 있는 카드는 나머지 영역을 비대화형으로 한다.

진입/복귀: 콜드 스타트는 기존 운전자 재확인 규칙 유지. 앱 홈 복귀는 현재 세션 확정·초안을 소비하지 않는다. 빈 DB는 '기록 없음'이며 '문제 없음'이 아니다. 저장 결과는 이전 이동과 무관하게 상세에서 확인 가능해야 한다.

### S02 차량 건강 상태
- 위: '확인한 차량 정보' 제목, SOC/누적거리/차종별 실제 지원 신호. 값·단위·앱 조회 시각·출처를 묶는다.
- 미지원/미수신/오래됨/최근 실패는 별도 라벨. 이전 유효값을 보이면 반드시 '이전 확인값' 표시. 미지원은 0%가 아니다.
- 중간: 근거 있는 충전량 안내와 '차량 데이터 분석', '저장된 차량 정보'. 이들은 수동 문제와 구분한 읽기 전용 관측이다.
- 하위: '운전자 지원'의 기존 위치 첨부/길 안내 지원 범위. 새 감시 기능으로 포장하지 않는다.
- 접힌 상세: SDK·capability·세션·원본 오류·원관측/조회 이력. 오류 요약에서는 다음 행동을 먼저 안내하고 상세 원문은 보존.
- 연결: 충전량 안내→기존 SOC_NOTICES, 데이터 분석→ANALYTICS, 관측→SNAPSHOTS→SNAPSHOT_DETAIL→HISTORY, 수신 상세→LOAD_DETAIL. 새로고침 버튼·polling을 UI 개편 핑계로 추가하지 않는다.

### S03 문제 남기기/수정
- 위: 제목·확정 작성자. 필수는 문제 종류와 상황만. 종류는 기존 분류 그대로 유지하고 레이블만 읽기 쉽게 한다. 시안의 4종은 배치 예시이지 운영 분류 축소 지시가 아니다.
- 본문: 종류 선택→상황 입력, 옆/아래 '음성 입력'. 음성 수신 중에는 취소와 진행 상태. 기존 ON_DEVICE/Locale.KOREA의 final과 ended 후에만 입력 반영. 수동 완료/타이머 성공 버튼을 재도입하지 않는다.
- '선택 정보 추가': 발견 시각·메모·기존 차량 snapshot 연결. 발견 시각과 수정 시각은 구분. 음성/위치는 자동 전송하지 않음.
- 행동: **저장**(주), **저장하고 AI 설명**(보조). 둘 다 실제 기록 commit·읽기 확인 뒤 이동한다. '저장하고'는 외부 전송까지 완료한다는 뜻이 아님을 한 줄로 알린다.
- 취소: 저장과 시각적으로 떨어진 조용한 버튼. 변경 있을 때 '계속 작성 / 내용 버리기', 일반 뒤로/홈은 초안 보관 후 이동. 취소와 뒤로를 같은 파괴 행동으로 처리하지 않는다.
- 저장 실패: 필드/저장소 원인에 따라 짧은 안내, 입력/작성자 유지, 재시도. 중복 클릭/진행 STT 중 저장 비활성. 수정은 original ID/revision·발견 시각·이력을 유지하고 충돌 시 덮어쓰지 않는다.
- 1차에서는 신규 폼 상태 머신을 만들지 않고 기존 RECORD/ACTION의 표현을 정리한다.

### S04 Gemini AI 문제 설명 및 음성
- 상단: '저장한 문제', source issue와 적용 revision. 저장 성공 안내는 지속하되 장문 정책 문구를 반복하지 않는다.
- 최초 전송 전: 종류·상황의 **전송 사본을 눈에 보이게**. 개인정보 제거 편집은 원문 편집과 명확히 구분. 동의가 필요한 내용은 접어서 숨기거나 기동의로 가장하지 않는다.
- '새로 설명 생성'은 명시적 외부 요청. 기존 결과 보기는 재호출하지 않는다. pending 회수와 신규 생성/저장 결과를 구분한다.
- 결과: '가능한 원인 / 추가로 확인할 점 / 정비소에 물어볼 내용'의 한국어 문단. 추정·점검 참고임을 짧게 표시. 자동 진단·수리 확정·안전 보장 금지.
- 하단: 결과 준비 시 '이 설명 음성으로 듣기', 재생 중 '음성 중단'. 기존 chunk/TTS callback·이탈/제한/취소 generation 보호 유지. 듣기는 모델 재호출이 아니다.
- 차량 참고 정보는 **기기에서만 보는 참고** 섹션으로 전송 사본과 분리. 차량값을 AI가 사용했다고 오인하게 나란히 연결선으로 그리지 않는다.
- 오류: 연결 실패→'기록은 저장되어 있어요. 연결 후 다시 시도해 주세요.' 할당량→'이번 사용 한도에 도달했어요. 저장된 설명을 볼 수 있어요.' 로그인/등록 오류는 해당 복구 행동 제공. 안전/보안 reason 자체를 없애지 않음.
- 복귀는 저장된 해당 문제 상세. source issue 버전 불일치·삭제·다른 사용자 캐시를 조용히 재사용하지 않는다.

### S05 기록·인계 목록
- 위: 제목, 문제 남기기. '다음 운전자 인계'는 이 허브에서 찾을 수 있으나 미확인 조건 진입이다.
- 기본 전체, 기존 전체/관리 중/완료/내 작성의 의미를 그대로 유지. wrap하는 큰 필터, 검색(본문·메모·분류)을 하나의 입력으로. 초기화는 조건이 있을 때만.
- 카드: 분류/문제 상황, 발견 시각, 작성 당시 이름, 수동 상태, 미확인 배지. 1카드 1상세 진입. 내부 ID/revision·모든 이력은 전면 노출하지 않음.
- 결과0건은 빈 DB와 검색 불일치를 다른 안내로 처리. 페이지/스크롤·검색/필터는 상세/도움말/AI 왕복 후 복원.
- 화면 제목 '문제/기록/저장 기록' 혼용을 '기록·인계'로 통일하지만 DB status enum이나 testTag를 이름 따라 변경하지 않는다.

### S06 문제 기록 상세
- 첫 블록: 상황·작성자·발견 시각·수동 상태. 변경 이력과 당시 차량 snapshot은 구분해 펼친다.
- 맥락 행동 1순위: 미확인 타인 기록이면 **인계 내용 확인했어요**, 확인된 기록이면 **점검 내용 남기기**. 읽음과 점검을 자동 연결하지 않는다.
- AI 블록: 저장 결과가 있으면 'AI 설명 다시 보기', 없으면 'AI 설명 보기'. 생성·전송·듣기는 AI 화면에서 각각 명시한다.
- '기록 관리'에 본인 ID 기준 내용 수정/논리 삭제. 수정·삭제를 화면 맨 위 네 버튼에 병렬로 두지 않는다.
- '점검/상태': 기존 네 수동 상태·조치/재발·정비 상담 요약·위치/길 안내 기능을 보존. 완료/재발은 필요한 확인과 메모 흐름을 유지.
- 상세 열기만으로 읽음/점검 이벤트를 생성하지 않는다. 삭제는 별도 확인, 복원/영구삭제를 구현한 것처럼 표시하지 않음.

### S07 다음 운전자 인계
- '현재 운전자가 아직 확인하지 않은 다른 운전자 기록'임을 한 줄로 설명. 미확정이면 먼저 기록 운전자 확인.
- 타인 미확인 목록→각 상세→명시적 확인. 확인 성공 후 해당 큐로 복귀하면 남은 건수 갱신. 한번에 모두 읽음은 초기 범위에서 제외.
- 전달은 이 기기의 로컬 프로필 간 공유. '다음 운전자에게 보내기'라는 원격 전송형 버튼을 만들지 않음.
- 하단 '다른 운전자에게 전달하려면'에 다음 사람이 자신의 프로필로 운전 시작하도록 설명. 이름 선택만으로 과거 작성자를 바꾸지 않는다.
- 예외: 같은 기록 수정/revision·재발의 미확인 판정은 기존 service 계약을 그대로 적용. 새 배지 계산으로 읽음 의미를 바꾸지 않는다.

### S08 설정·도움말 / 첫 안내
- 그룹1 기록 운전자 관리(등록·이름 변경·보관), 그룹2 화면(시스템/밝게/어둡게, 차량 표시·시각), 그룹3 도움말·AI/개인정보·앱/기술 정보.
- 기존 MENU의 전체 기록/내 작성/차량 진입은 제거한다. 전체 기록은 홈, 내 작성은 기록 필터, 차량은 홈 카드가 담당한다.
- 첫 안내는 신규 사용자에게 한 화면: '차량 상태를 확인하고, 문제를 남기고, 다음 운전자와 이어 보세요.' / '시작하기' / '나중에'. 설명을 읽어야 기록을 쓸 수 있게 강제하지 않는다.
- 사용법과 안내 재보기는 설정에 유지한다. 도움말 진입·안내 건너뛰기는 운전자 확정·동의·SDK조회·읽음 이벤트를 실행하지 않음.
- 예외 진단 상세와 AI 동의 철회/보존 정책은 일반 메뉴 단순화 대상에서 제외한다.

## 5. 실제 조작 흐름과 목표

탭 횟수는 **운전자 확정·정차 상태의 홈부터**, 필수 텍스트 입력/OS 권한/최초 로그인·동의 제외. 말하기/타이핑 시간도 제외하므로 전체 노력 감소를 뜻하지 않는다. 새 수치는 설계 목표이지 실행 계측 결과가 아니다.

| 과제 | 현재 코드 기준 경로 | 새 목표 | 판단 |
|---|---|---|---|
| 작성 화면 열기 | 홈 증상 남기기 1탭 | 홈 문제 남기기 1탭 | 이미 빠름, 단축 주장 안 함 |
| 기록 저장 | 작성 진입→필수 선택/입력→저장 | 동일 화면, 저장까지 2탭+입력 | 필수 종류 선택이 별도라면 +1, 기본 분류를 멋대로 자동 확정하지 않음 |
| 저장 후 AI 요청 | 저장하고 AI 설명→AI 새로 생성 | 동일 2행동(+홈 진입1) | 최신 구현이 이미 단계 축소. 새 연구 성과로 주장하지 않음 |
| 미확인 인계 확인 | 홈 확인할 카드→상세→명시 확인 | 홈 인계큐→상세→확인 3탭 | 큐 추가로 1탭 늘 수 있음. 1건일 때 홈 CTA를 상세로 직행시키는 최적화는 후속 실험; 시안은 일관된 큐 사용 |
| 전체 기록 | 홈 기록 확인 또는 상단 기록 | 홈 전체 보기 1탭 | 동일 속도, 같은 화면 내 중복만 제거 |
| 건강 상세 | 상단 차량 또는 홈 수치/메뉴 | 홈 차량 상태 보기 1탭 | 탭 수보다 목적 이름 개선 |
| 하위→홈 | 고정 홈 1탭 | 홈 1탭, 초안 보존 포함 | 필수 회귀 |
| 운전자 전환 | 운전자 선택→후보→운전 시작 | 홈 변경→후보→운전 시작 | 후보와 확정을 합치지 않음. 시안 단순 선택과 실제 계약 구분 |

## 6. A/B 실제 디자인 비교

독립 [HTML 시안](CARITDA_REDESIGN_20261111_PROTOTYPE.html)에서 같은 정보·동작을 A/B로 전환한다. 데이터는 모두 가상 예시. 두 안 모두 홈 상단 1개/하위 최대2개 탐색 버튼이며 별도 3~4탭 바가 없다.

| 항목 | A 실용 최소형 | B 브랜드 완성형 (추천) |
|---|---|---|
| 구성 | 선 구분, 평면 섹션, 사각에 가까운 버튼 | 우선 행동 카드, 절제된 청록 강조, 18dp 라운드 |
| 메뉴 수/흐름 | 동일. 최소 기능만 남기는 모드가 아님 | 동일. 시각 장식을 위해 경로 추가하지 않음 |
| 고령자 | 높은 단순성, 섹션 경계를 놓칠 위험 | 그룹·주행동 구분이 쉬울 가설, 카드 과분할 주의 |
| 차량 적합성 | 빠른 렌더링·낮은 표현 비용 | 움직임 없는 면·선 중심, 큰 터치와 대비 유지 |
| 구현 난이도 | 낮음~중간: 탐색/위계·문구 회귀 필요 | 중간: 동일 구조+토큰/상태·다중폭 조정 필요 |
| 위험 | 또다시 개발 도구처럼 보일 수 있음 | 카드 수가 늘면 원래 문제 재발 |

추천: **B의 시각 시스템 + A와 같은 정보량/동작 수**. 브랜드는 워드마크·문장·정렬·여백으로 표현한다. 장식 차 그림/실시간 점수/큰 AI 버튼/그라디언트/과한 애니메이션은 쓰지 않는다. 선호·이해도 우위는 사용자 시험 전 가설이다.

## 8. 반응형과 접근성

차량/폰 여부와 창 폭을 분리한다. 차량에서도 작은 창은 한 열이다. 기존 Android View 기반을 유지한다.
- 600dp 미만: 한 열. 600~839dp: 두 열 강제 금지, 콘텐츠 길이/유효 폭으로 선택. 840dp 이상+충분한 높이/기본 글자: 홈 두 열, 목록/상세 분리 pane는 후속 단계.
- fontScale≥1.5 또는 IME/짧은 높이: 한 열 우선, 버튼 wrap. 중요 요소의 고정 높이 금지. ime/systemBars/displayCutout 인셋 적용.
- 저장 행동은 폼 직후에 두며 키보드가 가리면 스크롤로 도달. 고정 bottom bar를 쓸 경우에는 IME 위로 올리며 본문을 덮지 않는다. HTML은 문서 스크롤이고 Android 인셋/IME 구현을 증명하지 않는다.
- 읽음·미점검·미지원·실패는 색 외 단어로 표현. 아이콘 전용 숨은 관리 버튼 금지. 필드 label은 hint와 분리하고 오류와 연결.
- 변경 후 포커스는 제목/오류/저장 결과로 예측 가능하게 이동. 키보드/rotary 포커스와 순서 확인. TalkBack은 실제 지원 기기에서만 검증 완료를 주장한다.
- 자동 팝업·자동 애니메이션·시선 유도 효과 없음. AI 장문은 주차 후 읽고, 음성 출력은 명시적으로 시작·중단.

## 9. HTML 구현 범위와 제한

구현: 홈/건강/작성/기록목록/상세/AI/인계/설정/도움말, A/B·차량/폰·테마·150%·예외 선택, 메모리 내 예시 저장·인계·초안 이동·오류 피드백.
표시만: 상태 변경, 점검 메모, 삭제, 관측 분석, 기술 상세, 개인정보 정책. 실제 기능 연결 지점이라는 안내를 띄운다.
음성은 입력 예시 문장/출력 상태만 시뮬레이션. Gemini 요청/로그인/차량 연결/파일 쓰기/서버/동기화는 없다. 새로고침하면 메모리 상태는 초기화된다. Android APK 빌드·에뮬레이터·실차·실제 접근성 적합성은 이번 시안 검증에 포함되지 않는다.

### AI 모드별 추가 정합성

증상모드의 명시적 요청 원칙을 SOC모드에도 적용하는 것은 제안이며 현재 코드의 자동요청을 이미 제거했다는 뜻이 아니다. SOC의 request_from_analysis 자동경로·하루/7일 범위 차이는 별도 회귀패치로 분리한다. 기록 상황 최대1000자와 AI 전송3~800자 차이는 전송사본에서 검증하며 원문을 무단으로 자르지 않는다.
