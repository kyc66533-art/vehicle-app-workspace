# CARITDA Simple UI·온보딩 구현 및 인수 결과

검증일: 2026-11-08 +09:00 (Asia/Seoul). 기준 main: `e5473532c639cd69d8e0a8017697ad6cbe66783d`.

Aside의 [온보딩 연구](research/CARITDA_ONBOARDING_UX_RESEARCH.md)와 [기존 UI 연구](research/CARITDA_UI_UX_RESEARCH.md)를 읽고 실제 Kotlin/View 화면에 반영했습니다. 기존 [AC01~AC28 결과](UI_ACCEPTANCE.md)는 당시 결과로 보존하며 아래의 신규 ON 검사를 대신하지 않습니다. CARITDA는 상표 검증 전의 가칭입니다.

## 실제 화면 변경

- 홈: CARITDA·사용법, 기록 이름/변경, 확인 가능한 범위, 읽지 않은 전달 기록/관리 중/완료/빈 상태, 기록 보기·문제 남기기·차량 정보. 문제 카드 전체·상담·SDK 로그는 각각 기록/상세 화면으로 이동했습니다. 기록 보기는 관리 중 기록을 우선 열고 모두 완료됐으면 완료 목록을 엽니다. 이전 목록 필터를 무심코 재사용하지 않습니다. 기존 초안 이어쓰기는 유지합니다.
- 차량 정보: 충전량·누적 주행거리의 이름/값/단위/수신 시각/오래됨/출처와 차량값 불러오기. 값 32sp, 항목·버튼 24sp, 주요 시간 22sp, 버튼 최소 76dp이며 내용에 따라 확장합니다. 숫자에 자릿수 구분을 적용하되 원본은 변경하지 않습니다. 연료 미지원은 접을 수 있는 제공되지 않는 항목에서 설명하며 0%를 만들지 않습니다.
- 불러오기 상세: SDK 2.3.2, Capability 상세, 원본 값/단위, 지원·유효·상태, 세션, 원본 오류, 출처 코드, 밀리초 시각을 남겼습니다. 원본 저장은 그대로이며 화면에는 최근 100건을 보여줍니다.
- 한 화면 첫 안내: 사용자가 지정한 제목·설명·현재 자동 감지 미지원 문구와 운전자 선택/안내 건너뛰기. 선택/건너뛰기는 안내 preference만 완료하며 기록 운전자를 확정하지 않습니다. 기존 설치 또는 저장된 운전자/문제/초안/관측이 있으면 자동 제안을 생략합니다. 신규 제안이 중단된 경우 pending 상태를 유지합니다.
- 사용법: 운전자 선택, 차량값 조회, 직접 기록, 다른 사람 기록 읽기, 정비 상담용 요약, 자동 확인의 현재 범위를 여섯 항목으로 설명합니다. 처음 안내 재보기·닫기와 기존 화면/초안 복귀를 제공합니다. 테마 선택은 사용법에 배치했습니다. 여러 팝업이나 연속 coachmark는 추가하지 않았습니다.
- 기본 화면에서 `Capability`, `RECEIVED`, `UNSUPPORTED`, `ERROR_…`, SDK·세션 코드를 제거했습니다. 사용자 화면은 ‘문제 남기기’, ‘아직 읽지 않은 전달 기록’, ‘관리 중인 기록’, ‘이 이름으로 기록을 남겨요’로 설명하며 저장 enum/과거 이력은 바꾸지 않았습니다.

## 데이터·안전·시각의 의미

문제 DB는 v2, 관측 DB는 v1 그대로입니다. 운전자 영구 ID·A/B·작성 당시 이름·인계·조치·재발·초안 스키마와 Vehicle SDK 2.3.2/PleosReadClient/CarSafetyGate는 변경하지 않았습니다. ObservationStore에는 읽기 전용 최근 조회 메서드만 추가했습니다. 최근 100회 이상 조회가 실패해도 그 이전의 유효 값을 찾습니다.

마지막 유효 값과 최신 시도는 별도로 조회합니다. 최신 실패나 오래됨이 있으면 ‘이전 값’과 원래 수신 시각을 표시합니다. 유효 0km·아직 미수신·미지원·권한 없음·응답 실패는 구분하며 TEST_ONLY를 차량 수신값으로 쓰지 않습니다. 10분은 화면 표시의 오래됨 기준으로 고장 기준이 아닙니다. 미래로 1분 이상 어긋난 수신 시각도 확인 문구를 표시합니다. 화면이 보일 때 표시 시각을 재평가하지만 SDK 재조회/백그라운드 수집은 하지 않습니다.

안전 상태 UNKNOWN/RESTRICTED에서는 기존 입력 차단을 유지합니다. 안내 중 제한되면 상태를 남기고 홈으로 돌아가며 허용 뒤에만 명시적으로 안내를 이어볼 수 있습니다. 안내·사용법·건너뛰기로 제한을 해제하거나 운전자/읽음을 확정하지 않습니다. 초안 실패 문구는 실제 성공하지 않은 보존을 보장하지 않도록 수정했습니다.

## 빌드·실행·자동 검사

- 기존 Windows/JBR 21.0.8/Gradle 8.11.1/API 34/Build-Tools 35.0.0 캐시를 이용한 offline `assembleDebug` 및 `assembleDebugAndroidTest` 성공. 최종 빌드 `BUILD SUCCESSFUL in 1m 1s`, exit 0.
- 기존 Pleos Connect v2.1.0, `emulator-5554`, API 34에서 앱·테스트 APK 모두 `install -r` Success. 앱/데이터 삭제·AVD 초기화·시스템 정책 변경은 하지 않았습니다.
- 기존 검사: `CARITDA_MVP_PASS checks=24`, `CARITDA_OBSERVATION_PASS checks=6`, `CARITDA_UI_PASS checks=27`. 운영 이전 비교 사본의 원래 문제 5건·이벤트 16건 및 원래 관측 보존도 `PRODUCTION_MIGRATION_PASS`로 재확인했습니다. 회귀 과정이 추가한 검증 기록은 삭제하지 않았습니다.
- 신규 검사: `CARITDA_ON_PASS checks=32`. 안내 정책, pending 첫 안내 UI, UNKNOWN 진행 차단, skip 무부작용, 재실행, 재보기/복귀, 홈 필터, 실제 SDK 조회, 기술 상세 분리, 초안 복귀, 기존 모든 운전자/문제/이벤트/settings/초안 행 동일성과 이전 관측 행 보존을 검사했습니다.
- SOC **15%**, 주행거리 원본 **1000000.0 km**를 실제 에뮬레이터 SDK로 읽고 저장했습니다. 기본 화면은 **1,000,000 km**로 표시합니다. 연료는 `ERROR_NOT_SUPPORTED_PROPERTY` 미지원이며 숫자를 넣지 않습니다. 실차 측정이나 앱 내부 가상값이 아닙니다. SOC 15%를 고장/즉시 정차 경고로 바꾸지 않습니다. 기기 수신 시각은 기기 시계·시간대 기준이며 PC 보고 시각과 같다고 가정하지 않습니다.
- 별도 격리 DB fixture에서 유효 0, 미수신, 성공 뒤 105회 실패, 15% 무진단, 10분 경계, 미래 시각, TEST_ONLY 배제를 검사했습니다. fixture는 앱 관측 DB에 삽입하지 않았습니다.
- 홈/기록/차량/운전자/사용법 × 320/480/600/840/1024dp 콘텐츠 폭 × fontScale 100/130/150/200% × 밝음/어두움 = **200개 렌더링 조합**에서 가로 넘침·말줄임·76dp 버튼 높이를 확인했습니다. 테스트 프로세스 리소스와 앱 테마는 원복했으며 Windows/Android 전역 글꼴을 바꾸지 않았습니다. 실제 OS 분할 창의 모든 크기/IME를 시험한 결과는 아닙니다.
- 실제 Pleos 화면의 홈·차량·사용법·재보기 화면 캡처도 검토했습니다. 최초 설치 UI는 사용자 데이터 보호를 위해 재설치 대신 안내 pending preference를 임시 설정해 시험한 뒤 원복했습니다. 실제 비어 있는 신규 설치 시험은 아직 하지 않았습니다.

## 검사 재현과 사용자가 확인할 순서

Android Studio에서 기존 `NextDrive-Pleos`를 열고 기존 AVD를 선택해 `app` Run을 누르세요. 이번 작업에서는 이미 APK를 교체 설치했으므로 파일 직접 편집이나 앱 삭제가 필요 없습니다.

1. 기록할 이름 선택 → 운전 시작. ‘이 이름으로 기록을 남겨요’를 확인해 주세요.
2. 홈에서 확인 가능한 범위와 읽지 않은 기록을 살펴보고 기록 보기로 이동해 주세요.
3. 차량 정보 → 차량값 불러오기에서 충전량·km·수신 시각·에뮬레이터 출처를 확인해 주세요.
4. 제공되지 않는 항목과 불러오기 상세를 열어 기본 화면과 상세의 차이를 확인해 주세요.
5. 사용법 → 처음 안내 다시 보기 → 닫기 → 사용법 닫기로 원래 화면에 돌아와 주세요.
6. 문제 남기기에서 임시 내용을 입력하고 사용법을 열었다 닫아 내용이 유지되는지 확인해 주세요. 기존 기록을 지우거나 데이터 초기화할 필요는 없습니다.

계측 실행은 테스트 APK 설치 후 아래 두 모드를 사용합니다. 첫 번째는 운영 앱에 검증용 프로필/문제를 추가하므로 기존 기록을 보존하고 추가 기록도 임의 삭제하지 않습니다. ON 모드는 사용자 초안이 이미 있으면 덮어쓰지 않고 해당 scratch 과제를 부분으로 기록합니다.

```text
adb shell am instrument -w -e onboardingOnly true com.nextdrive.pleos.test/com.nextdrive.pleos.MvpScenarioInstrumentation
```
