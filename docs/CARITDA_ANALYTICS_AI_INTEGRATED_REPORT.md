# CARITDA 차량 분석·자동 인사이트 통합 검증

작업 기준: 2026-11-08 Asia/Seoul, main `69d64efbd3ab756d883620fe9a7b15b20ce81ffa`. Pleos Connect v2.1.0/API34/Vehicle2.3.2, Android user10. CARITDA는 상표 검증 전 가칭입니다. **Stage1·2 로컬 기능 검증 완료, Stage3 AI는 사용자 설정 없음으로 인터페이스/로컬 검증까지만 완료**했습니다. 실차·실제 모델 성공 보고가 아닙니다.

## 1. 사용자 검수 문제의 실제 원인

새 백업의 일반 앱에는 현재 사용자 기록23건, SOC 사건0개가 있었습니다. 별도 validation 앱에는 사건3개/변경6개가 있었습니다. 기존 두 앱 전체 databases/shared_prefs/files를 별도 비공개 tar로 보존한 뒤 읽기 전용 사본으로 확인했습니다. 출처 불명 기록을 정리하거나 일반 DB를 초기화하지 않았습니다.

validation의 세 사건은 각각18→45%,6→29%,17→39%였습니다. 서로 다른 사건 ID와 진입/해제 원관측 참조를 갖습니다. 39/29/45는 현재 SOC가 아니라 **각 사건이 마지막으로 해제될 때 수신한 값**입니다. 일반 앱의100%와 서로 다른 앱 저장소이고, 이전 해제 기록은 다음100% 수신으로 덮어쓰지 않는 것이 맞습니다. 과거 기록을 현재값처럼 읽게 한 화면 표현이 주요 원인입니다. 세 사건의 실제 정렬에서는 entered와 last_at 순서가 같았으므로, 이 사례의 표시 순서 오류를 정렬 하나 때문이라고 단정하지 않습니다.

`notices()`는 이제 last_at→entered 순서로 조회합니다. 최근 실제 SOC/시각/출처/실패·오래됨을 별도 영역에 두고, 현재 안내/관측 상태와 접힌 이전 사건을 구분합니다. 한 사건 한 카드에 진입·해제 시각과 값을 표시하고 내부 UUID/행/규칙은 접힌 근거에 남깁니다. 기존 policy/episodes/changes/gaps 스키마·ID·원문을 변경하지 않습니다.

## 2. 버튼과 홈

CaritdaComponents의 모든 기본 버튼 상태에 명시적 경계를 추가했고, 보조 기능에도 원본 자체 제작 아이콘과 글자를 함께 표시합니다. 아이콘28dp/최소76dp 터치 목표와 focus/selected/pressed/disabled 상태를 유지합니다. 차량 정보의 분석 진입은 보조 위치에 추가하고 홈의 차량 수치/확인할 기록/두 주요 행동은 재설계하지 않습니다.

대비는 [WCAG](https://www.w3.org/TR/WCAG22/)의 일반 텍스트4.5:1/비텍스트3:1 원칙과 [Android Automotive의 큰 터치·일관된 표현](https://developers.google.com/cars/design/design-foundations/visual-principles)을 참고합니다. 토큰 계산과 실제 native layout 검사는 OEM HMI 인증/실사용자 사용성 인증이 아닙니다.

## 3. 원천 데이터와 범위

원본 ObservationRef(store UUID+row ID)를 재사용합니다. kind/raw/unit/receivedAt/recordedAt/source/support/valid/session/status/detail(GET 또는 CALLBACK)을 유지합니다. SnapshotStore의 기존 사용자 증상 연결은 그대로이며 새 분석이 임의로 새 링크를 만들지 않습니다.

SOC와 누적거리만 분석합니다. source=실제 SDK(에뮬레이터 또는 차량)만 허용하고 TEST_ONLY/출처 미확인은 제외합니다. 두 실제 출처가 함께 있으면 마지막 SDK 데이터 환경만 분석하고 다른 환경 제외 수를 표시합니다. 이것이 VIN/실제 물리 차량 식별을 뜻하지는 않습니다. 합성 규칙 fixture는 별도 validation DB/메모리에만 있고 일반 앱에 복사하지 않습니다.

## 4. 전처리·모집단·시계열

- SELECT는 worker에서 kind/recorded_at 기간과 최근2001행으로 제한하고, 최대2000행을 분석합니다. 하루/일주일/최근최대2000행을 선택할 수 있습니다. 제한됐으면 이를 표시합니다. redraw·차트 스크롤은 SDK 호출이나 전체 DB 분석을 시작하지 않습니다.
- 미지원/권한/연결·시간초과/결측·오류/범위·단위/미래·역순 시각/오래됨/반복/다른 출처·세션을 구분합니다. 오류를0으로 대체하지 않습니다. 오래된 유효 이력은 역사적 통계에 남기되 현재값으로 확정하지 않습니다.
- 입력 순서에서 시간 역순을 검출하며 오류를 숨기기 위해 먼저 시각순 정렬하지 않습니다. 세션·환경·저장소 변경/오류/중단 gap/10분 초과 간격에서 비교와 선을 끊습니다. 10분은 분석상 표시 기준이며 OEM 경고·효율 규격이 아닙니다.
- 조회 세션이 바뀌었다고 실제 차량이나 운행이 바뀐 것은 아닙니다. 현재는 비교를 보류하는 보수적인 경계로만 사용합니다. 새 GET이 중간에 들어가면 이전 callback 구간과 다음 callback 구간을 연결하지 않을 수 있습니다. 점선/공백은 실제 차량 고장이나 실제 운행 중단의 판정이 아닙니다.
- 유효 수신 수/최초·최근/최소·최대/단순 평균/직전 수신 대비 변화량/구간 증감/반복/공백을 계산합니다. 평균은 반복 수신을 포함한 **관측값 평균**이며 운행 시간 평균·충전 효율이 아닙니다. 시간당 변화율은 계산하지 않습니다.
- 누적거리 감소도 앱 수신값 차이이며 실제 이동 거리/계기판 결함이라고 확정하지 않습니다. 새 SOC callback이 누적거리도 최신으로 만들지는 않습니다.

## 5. 그래프와 자동 인사이트

VehicleChart는 Kotlin native Canvas/View입니다. x축은 실제 epoch 간격, 구간 단절은 별도 선, 기준은 점선, LowSocStore의 진입/해제 근거는 원으로 표시합니다. 수치 요약·contentDescription·원본 목록20건 페이지가 텍스트 대안입니다. 차량 측 측정시각은 제공되지 않으므로 앱 수신시각으로 표시합니다.

VehicleAnalytics는 값이 달라진 비교 가능 쌍/3개 이상 같은 방향/20%p 이상 탐색 후보/기존 낮은SOC 진입·해제/수신 공백/연속 수신 오류를 자동 탐색합니다. 20%p 탐색은 CARITDA의 설명 가능한 가설이며 배터리 고장 기준이 아닙니다. 기간·근거·규칙·변화량·품질·확정 불가 사항을 연결합니다. 같은 값은 원본에 남고 별도 변화 인사이트를 만들지 않습니다. 추세·연속 오류에는 안정된 키를 사용합니다.

낮은 SOC 조건은 **기존 LowSocStore changes**만 사용합니다. 별도의 경쟁하는 임계값 판정기를 추가하지 않습니다. 새 `caritda-analytics.db` v1에 파생 인사이트 ID/분류/시각/근거/facts를 저장하고 replay 중복을 막습니다. 기존4DB는 버전/열을 변경하지 않습니다. 원본 DB와 분석 DB가 하나의 원자 트랜잭션이라고 가정하지 않으며 실패 시 원본을 보존하고 이후 요청에서 재계산합니다.

자동 실행은 기존 진입 GET 완료와 실제 SOC callback 뒤입니다. worker는 요청을 합치고 화면에는 메모리 결과를 표시합니다. 앱이 종료된 동안 수신·분석이 계속됐다고 안내하지 않습니다. 새 데이터가 없을 때 redraw로 새 사건이나 SDK 조회를 만들지 않습니다.

## 6. 설명·행동·정비 상담

인사이트는 무엇이 달라졌는지/그 의미/다음 확인 행동/수신 시각을 먼저 보여줍니다. 근거 ID·규칙·품질은 상세에 둡니다. 낮은 충전량은 충전 계획/차량 표시 확인을 권하며 정비소 방문이나 부품 교체를 자동 권고하지 않습니다. 안전 위험 신호를 읽지 않았으므로 위험 등급을 높이거나 기존 수동 네 상태를 바꾸지 않습니다.

기존 상담 기록의 증상·시각·작성자·재발·상태·조치·연결 스냅샷은 유지합니다. 추가 질문은 실제 증상 본문을 인용한 ‘이 증상에 어떤 점검이 필요할까요?’ 한 문장이며 부품·저속·위치를 창작하지 않습니다. 복사는 명시적 조작으로만 합니다. 외부 정비소 전송/접수가 아닙니다.

## 7. 실제 AI의 차단 사유와 구현 경계

사용자는 이번 대화에서 **‘현재 없음 — 로컬 분석부터 진행’**을 선택했습니다. 승인된 HTTPS 중계/임시 앱 인증/모델·비용 설정이 없어 실제 모델 요청·응답·지연·요금·인증 실패·실모델 타임아웃은 미검증입니다. 모델을 임의 선정하거나 서버 배포·계정/비밀키 탐색·유료 호출·실사용 데이터 전송을 하지 않습니다. [공식 키 지침](https://developers.openai.com/api/docs/guides/api-keys)의 서버 보관 원칙을 유지합니다.

새 분석 전송 미리보기는 선택 신호/수치/수신시각/변화/통계/품질/한계만 보여줍니다. 이름/VIN/위치/연락처/로컬 UUID·row ID/전체 DB/증상 원문은 기본 제외합니다. 동의는 고정 payload hash와 묶고 취소할 수 있습니다. 현재 동의는 로컬 확인뿐이며 **AI 미연결로 외부 전송하지 않는다**고 명시합니다. 전송처럼 보이는 가짜 실행 버튼은 없습니다.

AnalysisExplanation은 구조 facts/근거 hash/허용 action/수치 대응/위험 문구를 검사합니다. 동의 없음·취소·다른 facts·창작 숫자·기존 숫자 뒤바꿈·수리/안전 확정·Mock 사칭을 validation에서 검사합니다. 수치와 시각은 검증된 facts에서 로컬로 표시하고 모델 자유문장의 숫자는 거부하는 보수적인 계약입니다. 숫자 집합 안에 든 두 값을 바꿔 쓰는 오류도 허용하지 않습니다. 실제 모델의 문장 의미 전체를 보장하는 안전 인증은 아닙니다. 현재 모델 응답 저장·실제 승인 서버와 전송/취소·모델별 스키마/실응답 표시·모델 품질 검사는 미완료입니다. 로컬 규칙 설명을 AI가 생성했다고 표시하지 않습니다.
