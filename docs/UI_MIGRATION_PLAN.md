# 운전자 모델 이전·복구 절차

## 2026-11-08 — 기록 수정·논리 삭제용 v3 추가

현재 문제 DB는 v3입니다. 기존 v2에 issues.deleted_at/deleted_by_id만 추가하며 기존 운전자·문제·이벤트·초안·관측은 보존합니다. 원본 백업, 사본의 예외 롤백/전체 열·행/반복 이전 검사 후 실제 운영 APK를 교체했습니다. 운영 이전 후에도 모든 기존 열과 행이 동일하고 삭제 표식0건, 외래키 정상, 관측 DB 해시 불변을 확인했습니다. [신규 검증·보존 정책](RECORD_RELIABILITY.md)을 따릅니다. 아래 v1→v2 기록은 과거 사실로 보존합니다.

실제 DB 적용 전 절차(2026-11-07): 앱을 force-stop한 뒤 기존 문제 DB/관측 DB와 journal 및 이전 APK를 `.tools/ui-migration-backup/`에 바이너리 그대로 보관했습니다. 앱 전용 files에도 비교용 DB 사본을 보관했습니다. 개인정보를 포함할 수 있어 이 파일들은 게시하지 않습니다.

v2는 기존 v1의 모든 열과 행을 보존하고 drivers, drafts, 작성자 ID/당시 이름 snapshot, draft 중복 방지 인덱스만 추가합니다. A/B는 영구 legacy ID로 유지합니다. 신규 설치에는 가짜 A/B를 만들지 않습니다. 관측 DB는 변경하지 않습니다.

실제 적용 전 독립 v1 fixture에서 전체 원본 열/이벤트 순서/확인/재발/현재 운전자를 비교하고, 업그레이드 중 강제 예외를 넣어 SQLiteOpenHelper 트랜잭션의 스키마·행·user_version 롤백을 검사합니다. 성공 이후 반복 실행·재연결과 신규 운전자/이름 snapshot/보관/초안 중복 저장을 검사합니다. 통과 전에는 실제 앱 Activity를 열지 않습니다.

실제 적용은 사전 fixture 통과 후 수행합니다. 앱 전용 v1 사본과 운영 DB의 원래 문제/이벤트 열을 전수 비교하고 관측 DB도 사본과 비교합니다. 실패하면 앱 실행을 중단하고 원본/실패 DB/백업을 모두 보존합니다. 자동 drop/recreate, 앱 데이터 지우기, 무조건 이전 APK 설치·DB 덮어쓰기는 하지 않습니다.

복구가 필요하면 먼저 앱을 닫고 실패 상태 DB와 원본 백업의 무결성을 확인합니다. 스키마 v2를 이전 APK로 직접 열면 안 됩니다. 원인에 따라 전진 수정 또는 별도 복구 사본에서 검증 후 사용자가 확인한 복원 절차를 사용합니다. 실제 기록을 덮어쓰는 복구는 별도 승인을 받습니다.

후속 UI 인수는 Aside의 AC01~AC28을 기준으로 하며 실제 결과는 `docs/UI_ACCEPTANCE.md`와 `docs/CODEX_PROGRESS.md`에 기록합니다.
