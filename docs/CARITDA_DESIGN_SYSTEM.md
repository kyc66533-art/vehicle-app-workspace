## 콘셉트와 공식 근거의 구분

장식 대신 **정보의 순서, 정렬, 여백, 상태의 정확성**으로 차분한 차량 화면을 만듭니다. 기본 사용자를 처음 사용하는 일반 운전자와 60대 이상 사용자로 두며 별도 고령자 모드를 요구하지 않습니다.

[Pleos UI 원칙](https://document.pleos.ai/docs/connect/guide/docs-design/Introduction/intro)은 인지 부담 감소, 일관된 표현, 짧은 시간의 정보 파악, 충분한 대비를 제시합니다. 핵심 정보부터 보여주고 입력 반응이 지연되면 진행 상태를 표시하는 방향을 적용했습니다. 공식 문구의 시간 목표를 실제 반응 속도/사용성 시험 통과로 주장하지 않습니다.

[Display Layout](https://document.pleos.ai/docs/connect/guide/docs-design/getting-started/layout)은 앱 창과 Driving View·상태 표시줄·GNB를 구분하며 창의 가로/세로 대응을 설명합니다. 앱은 제공된 창 내부만 사용합니다. 시스템 홈/OS 표시를 구현하거나 덮지 않습니다.

[Typography](https://document.pleos.ai/en/docs/connect/guide/docs-design/foundations/typography)는 중립적인 글꼴과 정보 계층을 권고하고 System UI 글꼴 자료로 Asta Sans를 연결합니다. 이번에는 설치/라이선스 확인이 필요한 폰트를 추가하지 않고 기존 시스템 sans-serif와 한글 fallback을 사용합니다. Asta Sans나 현대차 전용 폰트가 실제 적용됐다고 주장하지 않습니다.

[현대차그룹 공식 소개](https://www.hyundaimotorgroup.com/ko/story/pleos-connect-next-generation-infotainment-system)의 단순한 학습 구조, 분리된 앱 영역, 일관된 글꼴/아이콘 방향을 참고했습니다. 기사 고해상도 이미지 직접 읽기는 도구 fetch 오류로 완료하지 못해 세부 픽셀 분석이라고 표현하지 않습니다. 공식 문서/설계 구조와 실제 실행 중인 Pleos 시스템 영역을 대조했습니다.

[Android for Cars sizing](https://developers.google.com/cars/design/automotive-os/design-system/sizing)의 76×76dp는 주행 중 선택 용이성의 차량 설계 기준입니다. CARITDA는 정차용 앱의 보수적인 터치 목표로 채택합니다. 모든 Pleos 앱에 적용되는 법적 인증값이라고 설명하지 않습니다. 기존 CarSafetyGate/DO 미선언 상태는 그대로 유지합니다.

공식 .fig 디자인 자산 링크는 있지만 이번에 다운로드/재배포 허용 조건을 확인하지 못했습니다. 자산·브랜드 로고·현대차/제네시스 아이콘을 복제하지 않았습니다. **아래 팔레트·수치·컴포넌트·Canvas 아이콘은 CARITDA 자체 제안**이며 공식 브랜드 토큰이 아닙니다.

## 간격·카드·버튼·아이콘

- 간격 토큰: 4/8/12/16/24dp. 바깥 좌우24dp, 카드 내부 좌우24·상하20dp, 카드 사이16dp, 열 사이16dp. 탐색 바는 간격8dp를 사용합니다.
- 카드 곡률18dp, 버튼/입력 곡률12dp, focus/선택 경계2dp. 카드 그림자·그라데이션·네온·장식 애니메이션은 없습니다. 버튼의 기본 native elevation/stateListAnimator도 제거했습니다.
- Primary는 절제된 청색, Secondary는 중립 면, Quiet는 배경과 같은 면, Danger는 삭제 행위의 글자 강조입니다. 모든 버튼을 흰색 사각형으로 그리지 않습니다.
- 모든 주요 터치 목표는 최소76dp입니다. 긴 한국어는 글자 축소/말줄임 대신 높이를 늘립니다. 선택은 체크/선택됨/접근성 상태, focus는 별도 경계, disabled는 글자/경계로 표시합니다.
- 직접 그린 24단위 outline 아이콘을 사용하며 버튼24dp·정보 카드28dp로 표시합니다. 이는 공식 아이콘 자산/48dp 제작 격자를 복제한 것이 아닙니다. 중요한 행동은 항상 글자와 함께 둡니다. 큰 글꼴의 좁은 탐색 바는 아이콘을 생략해 글자를 보존합니다.
- Native DatePicker/TimePicker/확인창을 유지합니다. 기본 날짜/시간과 안전 확인을 자체 위젯으로 다시 만들지 않습니다. 이 영역의 모든 세부 토큰까지 통일된 OEM 스킨이라고 주장하지 않습니다.

## 상단 탐색과 화면 이동

고정 AppHeader는 본문 ScrollView 밖에 있습니다. 여유 창은 홈/기록/차량 정보/메뉴, 작은 창·큰 글꼴·작성 화면은 홈/메뉴입니다. 기본 분기점800dp와 높이360dp는 자체 제안입니다. 폰트150% 이상에서 보조 탭을 접고 글자를 우선합니다.

이전과 화면 제목은 별도 PageHeading 한 영역으로 묶습니다. 넓은 화면에서 이전 버튼은 작은 선행 행동이고 제목은 옆에 놓습니다. 좁은 화면은 줄바꿈해 뜻을 보존합니다. 홈은 앱 내부 HOME, 이전은 직전 화면입니다. OS 홈 Intent를 추가하지 않습니다.

이름/내 작성/조회 기록/사용법·테마는 메뉴로 이동했습니다. 넓은 창의 메뉴는 이미 상단에 있는 기록·차량 탭을 다시 나열하지 않습니다. 메뉴는 실제 버튼으로 열며 숨은 제스처가 필수 경로가 아닙니다.

목록 조건·가능한 픽셀 위치·초안은 기존 경로로 보존합니다. 안전 상태 변경 시 기존 정책대로 복잡한 입력을 닫고 초안을 남깁니다. 캐시한 이전 버튼 객체를 실행하는 경우에도 현재 안전 상태를 다시 검사합니다. 낮은 높이/큰 글꼴에서 긴 성공·오류 안내는 본문 스크롤 안에 두어 입력 공간을 없애지 않습니다. 메시지를 자동으로 지우거나 Toast만으로 끝내지 않습니다.

## 차량 정보·조회 이력

기본 화면은 두 수치 카드, 항목별 시간/실패, 출처, 명시 새로 조회와 조회 기록입니다. 연료 미지원은 접힌 제공되지 않는 항목에서 설명하며0%로 표시하지 않습니다. 값 없는 상태는 확인 전/값 없음으로 표현합니다.

이력은 최근3건→전체 이력의20건 페이지→선택한 조회 내용 순서입니다. 같은 값 재조회/이전 조회와 달라진 정보/처음 저장한 조회를 구별합니다. 날짜는 기기 시간대, 순서는 저장 순서입니다. 서로 다른 세션·환경의 수신을 실제 물리 변화나 고장 회복으로 단정하지 않습니다.

선택한 조회는 구조화된 MetricCard를 사용하며, 반복 장문 snapshotText()는 없앴습니다. 자세한 수신 기록을 펼치면 SDK/Capability·지원/유효성·원본/단위·앱 수신시각·차량 측 시각 미제공·저장소UUID/행ID·세션·오류 원문이 남아 있습니다. 추가 SnapshotStore.timeline/snapshotCount는 SELECT뿐이며 스키마·원본·연결을 바꾸지 않습니다.

## 증상·기록·점검

기본 작성은 증상 버튼→짧은 상황→저장입니다. 발견 시각/메모/차량 정보 함께 저장은 선택 펼침 영역입니다. 기존 입력 한도·원 작성자·발견 시각 정책은 유지합니다. 선택 영역을 접거나 홈으로 이동해도 입력/연결 선택을 임의 폐기하지 않습니다.

기록 카드는 증상/사용자 상태→본문 미리보기→작성자·시각→내용 보기 순서입니다. 전체/관리 중/완료/내 작성·검색·초기화는 그대로입니다. 상세는 원문→연결 차량 정보→본인 수정·삭제→점검·상태→재발/상담→역순 이력입니다. 네 상태의 의미와 작성자 권한을 바꾸지 않습니다.

정비 상담용 요약에는 기존 전체 원문/이력과 실제 선택한 조회의 간단한 수치/시각·상세 이동을 제공합니다. 현재값을 과거 증상 발생 당시 값으로 바꾸지 않습니다. 삭제는 기존 논리 삭제이며 숨김/읽음/카드 갱신으로 상태를 바꾸지 않습니다.

CaritdaDesign.kt는 토큰/Canvas 아이콘/native View, VehicleUi.kt는 숫자·출처·원본 설명의 읽기 전용 표현입니다. MainActivity는 기존 안전·이동·입력 조정을 유지합니다. Repository/Service/ObservationStore/스냅샷 저장 의미를 UI 컴포넌트에 옮기지 않습니다.

향후 실제 신호 판단이 검증되면 별도 domain 결과를 AttentionContent와 같은 표시 모델에 전달할 수 있습니다. AI 설명도 검증한 근거의 보조 상세 위치에 추가하는 방향입니다. UI가 판정을 만들거나 미래 기능 버튼을 먼저 보여주지 않습니다. 이번에는 AI·경고등·자동 회복·폰·정비소 기능을 추가하지 않았습니다.

## 60대 이상 사용자 검수

기본 글자·명확한 동사·큰 타깃·선택 체크·저장 결과·명시적 취소를 모든 사용자에게 제공합니다. [실제 과제 검수표와 실행 결과](DESIGN_ACCEPTANCE.md)를 사용하세요. 자동화의 화면/대비/회귀 검사를 사람의 이해도 시험으로 바꾸어 보고하지 않습니다. 실제60대 이상2~3명의 독립 과제 시험은 아직 수행하지 않았습니다.
