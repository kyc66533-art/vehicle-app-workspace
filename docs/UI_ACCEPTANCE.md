# CARITDA 운전자·UI M0 구현과 인수 결과

검증: 2026-11-07, Asia/Seoul. 기준은 Aside의 `docs/research/CARITDA_UI_UX_RESEARCH.md` 전체와 특히 4~10장입니다. 연구 파일은 수정하지 않았습니다. CARITDA는 상표 검증 전 가칭입니다.

## 사용 방법

1. 기존 앱을 실행합니다. 기존 설치의 운전자 A/B는 이전되어 선택 목록에 남습니다. 신규 설치에는 가짜 A/B를 생성하지 않습니다.
2. `운전자 추가`에서 이름/별명을 등록합니다. 회원가입·메일·비밀번호는 없습니다.
3. 사람 카드를 선택하고 화면 아래의 `운전 시작`을 누릅니다. 후보만 선택하거나 취소하면 현재 운전자는 바뀌지 않습니다. 시작 버튼은 스크롤과 별개로 유지됩니다.
4. 홈에서 기록 운전자·미해결·미확인 인계를 확인하고 `문제 기록`을 누릅니다. 상세에서 명시적으로 `내용을 읽었어요`를 눌러야 확인 이력이 생깁니다.
5. 홈/문제/차량 메뉴를 사용합니다. 좁은 창과 큰 글꼴에서는 `메뉴`를 눌러 세로로 탐색합니다. 상담 요약은 문제 목록/상세에 있습니다.
6. 이름 수정·보관은 기록 운전자 변경 → `운전자 관리`에 있습니다. 현재 운전자는 다른 사람으로 시작한 뒤 보관할 수 있습니다. 과거 기록은 삭제하지 않습니다.
7. 작성 중 내용은 원 작성자와 함께 보존됩니다. 다른 사람으로 전환하려면 먼저 저장하거나 `작성 취소`를 확인해야 합니다. 재실행 후 원 작성자로 운전 시작 → `계속 작성`합니다.
8. 화면 아래의 `화면 테마`로 시스템/어둡게/밝게를 바꿀 수 있습니다. OS 설정은 변경하지 않습니다.

모든 입력·운전자 변경은 실제 AAOS UXR가 허용한 경우에만 가능합니다. 운전 시작은 기록 주체 확인이며 차량 시동·OS 계정·시트 변경이 아닙니다. 플랫폼의 입력 허용은 물리적 기어 P 인증과 동치가 아닙니다.

## 데이터 모델과 이전

문제 DB는 기존 이름 `caritda_v01.db`를 유지하고 user_version만 1→2로 이전합니다. 기존 reporter/actor 문자열, 원문·시각·상태·revision·이벤트 ID/순서를 유지하며 drivers/ID 참조/당시 이름 snapshot/drafts/중복 초안 확정 인덱스를 추가합니다. A/B는 동일한 영구 legacy ID입니다. 신규 운전자는 UUID를 사용합니다. 이름 변경은 profiles만 갱신하며 과거 snapshot은 바꾸지 않습니다. 보관은 archived 표시이며 물리 삭제 기능이 없습니다.

SQLiteOpenHelper 업그레이드 트랜잭션으로 오류 시 DDL/행/user_version을 롤백합니다. 중복 확인은 issue+revision+actor ID로 유지합니다. 문제 확정은 draft ID를 issue ID로 사용하며 같은 저장을 반복해도 하나만 생성합니다. 조치/재발에는 unique draft ID를 사용하고 확정과 초안 제거를 같은 트랜잭션으로 처리합니다.

기존 enum 소스는 영구 ID/표시 이름 모델로 바꾸되 A/B 상수는 이전·회귀용으로 유지했습니다. DB의 기존 enum 문자열 열은 삭제하지 않았습니다. 관측 DB/스키마와 Pleos SDK 코드는 변경하지 않았습니다.

이전 전에 앱을 닫고 두 DB/journal와 이전 APK를 프로젝트 내부 `.tools/ui-migration-backup/`에 바이너리 백업했습니다. 앱 전용 files에도 비교 사본을 보관했습니다. 백업/DB/키는 게시하지 않습니다. [복구 계획](UI_MIGRATION_PLAN.md)을 따르며 자동 덮어쓰기 복구는 없습니다.

## 실제 검사 결과

환경: 기존 Windows/JBR21.0.8/Gradle8.11.1/Platform34/Build-Tools35.0.0, Pleos Connect v2.1.0 emulator-5554, Vehicle2.3.2. 기존 환경을 재설치하거나 초기화하지 않았습니다.

- 단계별 앱/계측 APK 빌드 성공. 최종 assembleDebug/assembleDebugAndroidTest **52초, exit 0**. Deprecated back navigation 경고가 남습니다.
- 실제 운영 DB 적용 전 **MIGRATION_PASS checks=18**. 독립 v1 fixture의 A/B·확인·조치·상태·재발과 모든 원래 필드를 비교하고, 중간 예외의 rollback, 재연결·반복 이전, 신규 설치, snapshot, 보관, 초안 idempotency를 검사했습니다. 최종 APK에서도 재통과했습니다.
- 실제 기존 **문제 5건·이벤트 16건의 모든 원래 열/ID/관계/순서가 보존**됐습니다. 기존 관측 행도 비교 사본과 동일하게 보존됐습니다. 이후 테스트가 추가한 문제/프로필/관측은 구분하여 보존했습니다. 검증용 프로필은 `검증` 접두사를 사용하며 정상 완료 시 보관합니다. 초기 중단된 검사에서 만든 검증용 프로필/카드는 삭제하지 않았습니다.
- **CARITDA_MVP_PASS checks=24**, **CARITDA_OBSERVATION_PASS checks=6**, **CARITDA_UI_PASS checks=27** 통과. 합계 57개 런타임 검사이며 별도 이전 검사 18개까지 합계 75개입니다. Aside AC 28개가 전부 통과했다는 의미는 아닙니다.
- 실제 SDK: SOC **100%**, 누적 주행거리 **0.0km**, 두 Capability **READ**. 연료는 **ERROR_NOT_SUPPORTED_PROPERTY**로 값 없이 미지원 저장. 출처 **PLEOS_EMULATOR_SDK**, 실차와 구분합니다. 마지막 통합 검사 세션 `48861d71-6288-4b38-afc3-9dd1c0411794`.
- 실제 키보드로 임시 초안을 입력한 뒤 force-stop/cold start → 원 작성자로 시작 → 계속 작성에서 내용 복원 확인. 이후 명시적 취소로 해당 임시 초안만 제거했습니다. 기존 확정 기록은 보존했습니다.
- 320/480/600/840/1024dp는 실제 Activity 콘텐츠 폭을 제한하여 홈 CTA와 터치 높이를 검사했습니다. 폰트 100/130/150/200%는 테스트 프로세스의 Resources만 변경하여 CTA 확장/비말줄임을 확인한 뒤 원복했습니다. OS 전역 글꼴 설정은 바꾸지 않았습니다.
- 밝은/어두운 CTA 실제 전경·배경 색상에서 대비 4.5:1 이상을 계산했습니다. 모든 focus/disabled/네이티브 picker 대비 감사는 아닙니다. 실제 화면 캡처를 확인했고, 실제 Pleos 분할 창 전환 후 전체 창에서 홈 복원도 관찰했습니다.
- 최초 확장 검사는 상태 대화상자를 Activity decor에서 찾으려다 실패했습니다. 별도 창의 접근성 노드를 찾도록 테스트를 수정한 뒤 최종 전체 검사를 통과했습니다. 이 중단 시 생성된 시험 기록도 삭제하지 않았습니다.

## 설계 조정과 남은 작업

- SDK가 이미 실제 검증되어 차량 탭은 이번 범위에 포함합니다. 경고 도움말/분석 같은 미구현 M1 메뉴는 추가하지 않았습니다.
- 넓은 창도 단일 콘텐츠 열을 유지했습니다. 현재 사건 중심 동선을 단순화하고, 검증되지 않은 두 pane 압축을 피하기 위한 선택입니다. 모든 화면 2-pane은 후속 검토입니다.
- 후보 선택과 자주 쓰지 않는 수정·보관을 별도 화면으로 분리하고 운전 시작은 고정 하단에 배치했습니다. 낮은 창/확대에서는 본문 전체 스크롤로 접근합니다.
- 초안은 별도 비확정 SQLite 테이블을 사용합니다. 앱 전용 cache 파일 대신 동일 DB의 원자적 확정/제거와 draft ID 중복 방지를 활용하기 위한 선택입니다.
- 이름 상한은 NFC 후 Unicode code point 12개입니다. 완전한 grapheme cluster 12개와 다를 수 있어 emoji 조합 사용성은 후속 확인 대상입니다.
- 차량값 ‘오래됨’은 수신 후 10분이라는 표시용 앱 기준이며 OEM 이상/고장 임계값이 아닙니다. 상시 수집이나 자동 감지로 확장하지 않았습니다.
- Lint 결과는 최신 진행 기록을 따릅니다. Release·실차·주행 전환·TalkBack/rotary·고령 사용자 시험은 미완료입니다. 다음 단계는 부분 검증된 AC19~26을 실제 창·입력 장비에서 보강하는 작업입니다.
