## 1. 기존 CARITDA UI·UX 주요 문제

홈·기록·차량·메뉴 전역 탐색과 본문/메뉴 진입이 반복된다. 홈은 차량수치 먼저, 운전자의 미확인·점검할 일은 뒤다. 긴 설명 중 일부는 최신기능과 불일치한다. 실제AI/구형전송없는동의UI가 병존한다. 이미 디자인토큰/큰터치/다크모드가 있으므로 단순히 '디자인 없음'이 아니라 **정보위계와 행동의 일관성 부족**으로 진단한다.

MainActivity22개 Screen, PortableAiActivity 증상/SOC모드, 공통 다이얼로그와 컴포넌트를 코드로 조사했다. 상세 위치는 AUDIT에 있다.

## 2. 삭제·통합·수정할 버튼과 설명

상단 기록·차량 탭, 홈 자신의 홈버튼은 제거한다. 메뉴의 내작성은 기록필터로, 조회기록은 차량건강 하위로 옮긴다. 초기화/전체복귀의 중복은 조건초기화1개로 정리한다. 목록에서 새작성, 상세에서 AI, 하위에서 홈은 다른맥락의 유용한 빠른접근이므로 유지한다.

SDK/검증상태/raw/session은 상세로. 출처·신선도·미지원·동의·안전·저장실패는 필요한자리에서 짧게 유지한다. AI미연결/자동수집부정/구형버튼명은 모드별 실제구현에 맞게 고친다.

## 3. 새 상단 탐색 구조

홈: 브랜드(버튼아님)+설정·도움말1개. 하위: 이전/화면제목/홈 최대2개. 이전은 출발화면·목록조건, 홈은 앱첫화면이며 OS홈이 아니다. 초안보존 실패면 이동을 막는다. 새 전역AI/Gleo메뉴는 없다.

## 4. 홈 화면 정보 구조

기록운전자 → 지금확인할일(타인미확인 우선) → 문제남기기 → 일부차량정보와실제확인시각 → 전체기록. 차량건강·AI문제설명·기록/인계의3영역을 유지하되 AI는 저장문제의 맥락에서 접근한다. '정상' 건강점수·자동고장진단은 만들지 않는다.

## 5. A/B 디자인 시안과 추천

A는 선/정렬 중심의 극단적 실용형. B는 같은기능·같은메뉴수에 청록강조·우선카드·브랜드타이포를 더한다. **B추천**, 다만 카드/장식/동작수는 늘리지 않는다. HTML에서 A/B·테마·차량/폰·150%·예외를 전환한다. 선호우위/만족도향상은 아직 가설이다.

## 6. 고령자·초보자 접근성

아이콘+명확한라벨, 76dp터치하한 보존, 큰글자한열/버튼줄바꿈, 색외상태단어, 저장/취소/삭제 분리, 오류후다음행동, 운전자변경과인계확인 위치고정. 실제노년/초보형성과제를 후속계획으로 명시했다. 자동렌더 통과를 사용성검증으로 대체하지 않는다.

## 7. 차량 화면과 스마트폰 화면 설계

앱창 내부만 쓰고 OS상태/DrivingView/공조/GNB를 그리거나 덮지 않는다. 차량와이드2열→작은창/큰글자1열. 폰세로는 같은순서로 재배치. 홈/건강/작성/AI/목록/상세/인계/설정/도움의9개 시안화면을 포함했다. native 설계는 IME/insets·높이변화까지 별도 검사한다.

## 8. 스마트폰 실제 실행 가능성과 남은 과제

현재 Manifest의 automotive required=true, android.car/무조건Pleos의존, 비차량UNKNOWN gate 때문에 폰정상실행을 주장할 수 없다. :mobile독립모듈을 먼저 권고하고 platformflavor는 후속검토한다. 현재Firebase는AI인증이며 SQLite기록동기화가 아니다. 가족기기공유에는 서버·멤버권한·충돌/오프라인·보존/철회·개인정보 설계가 추가로 필요하다. Android Auto투사는 또별개로 미구현이다.

## 9. 기존 기능·DB·인증·안전 제한 보존

이번 작업은 기존 Kotlin/Gradle/Manifest/DB/운영설정/기존연구를 수정하지 않았다. 최신저장→AI/STT/TTS기능을 미구현으로 되돌리지 않는다. issue/driverID·원작성자·발견시각·revision·4수동상태·이력·초안·논리삭제, 관측출처/불변snapshot, Firebase/Keystore/동의/할당량/pendingUNKNOWN/Gleo신뢰검사를 보존한다. 제한/미확인시 입력불가, 모델호출/배포0회다.

## 10. Codex 구현 우선순위와 최종 개발 프롬프트
