## 현재 우선 규칙 — GitHub 연결 도구로 작업 완료 직후 게시

로컬 Git 연결 작업은 사용자 지시에 따라 중단했습니다. 기본 게시 경로는 이미 인증된 `codex_apps.github`입니다. 로컬 Git/GCM/clone/push, github.com:443 및 루트 `.git` 접근 재시도는 수행하지 않습니다. 기존 로컬 스크립트와 연결 안내는 보존하되 실행 지시로 해석하지 않습니다.

매 개발 작업 완료 시 별도 업로드 요청 없이 다음을 수행합니다.

1. 연결 도구로 현재 main 커밋과 트리, 변경 대상의 기존 blob SHA를 읽고 로컬 기준 내용과 대조합니다.
2. 이번 변경 파일을 검토하고 가능한 검증·공유 안전 검사를 수행합니다. 문서 변경은 문서 검사로 게시할 수 있고, 검증에 실패한 앱 소스는 제외합니다. 빌드 불가를 성공으로 기록하지 않습니다.
3. `docs/CODEX_PROGRESS.md`에 갱신 시각, 완료 작업, 변경 파일, 실제 검사 결과, 오류·미구현·다음 작업을 기록합니다.
4. 현재 main 트리를 기반으로 검증된 명시적 변경 파일만 담은 트리를 만들고, 현재 main을 부모로 커밋합니다. 모든 로컬 파일을 재업로드하거나 누락 파일을 삭제하지 않습니다.
5. 기대 HEAD를 지정하고 강제 갱신 없이 main에 반영합니다. 기준 HEAD/파일 SHA 변경이나 충돌 시 중단하고 보고합니다. 기존 Codex/Aside 이력과 `docs/research/**`는 보존합니다.
6. 원격 main·커밋 부모·게시 파일의 blob SHA를 확인하고 나머지 파일 SHA가 바뀌지 않았는지 검사합니다. 커밋 ID를 최종 응답에 제공합니다.

결과는 **'GitHub 연결 도구를 통한 게시'**라고 명시합니다. 로컬 Git push 성공이라고 표현하지 않습니다. 자기 자신의 커밋 SHA를 보고서에 넣기 위한 반복 커밋은 만들지 않습니다. 현재 활성 규칙은 루트 `AGENTS.md`에 저장되어 있습니다.

## 이전 검토 기록 — 로컬 Git 경로는 현재 보류

아래의 로컬 Git 우선 절차·최초 연결·직접 push·보조 스크립트 내용은 이전 검토 기록입니다. 현재 작업에서는 실행하지 않으며 위 연결 도구 절차가 우선합니다.

사용자는 검증된 개발 작업 완료 시 명시적으로 변경한 파일과 진행 보고서를 자동 커밋·게시하도록 상시 승인했습니다. 매번 업로드 요청이나 승인을 다시 받지 않습니다. 설치와 최초 인증은 별도 승인 대상입니다. 30분 예약 작업보다 Codex의 작업 완료 절차를 우선하며 스케줄러는 등록하지 않습니다.

루트 `AGENTS.md`가 이 규칙을 다음 세션에도 전달합니다. 지침은 작업 절차이며 Windows 서비스나 성공을 보장하는 후크가 아닙니다. 새 세션에서도 이 프로젝트에서 작업하고 적용된 지침·도구 권한·인증 상태를 확인해야 합니다. 별도 Codex 프로세스는 실행하지 않습니다.

공식 근거: [OpenAI의 AGENTS.md 안내](https://developers.openai.com/codex/guides/agents-md). 프로젝트 루트에서 시작하는 세션과 Git 루트 아래 경로의 지침 탐색 방식이 다를 수 있으므로, 로컬 Git 연결 전에는 이 작업 폴더에서 세션을 시작합니다. 루트 지침의 파일 크기도 기본 제한 32 KiB 이내로 유지합니다.

현재 Git은 `C:\Program Files\Git\cmd\git.exe`에 설치되어 있습니다. 이 세션의 PATH에는 없으므로 절대 경로를 사용합니다. GCM은 설치·기본 helper 등록이 확인됐지만 Windows 자격 증명 저장소 접근에 실패했습니다. GitHub HTTPS 연결도 실패했으며, 로컬 최초 인증/원격 clone/push는 미검증입니다. 설치가 없는 과거 상태는 아래의 초기 기록으로만 해석합니다.

PowerShell 정책은 `Restricted`입니다. `Set-ExecutionPolicy`, `-ExecutionPolicy Bypass`, 보안 해제 없이 직접 Git 명령과 읽기/검사 명령으로 완료 절차를 수행합니다. `.ps1` 보조 도구 실행은 필수 조건이 아닙니다. Git 설치·로컬 최초 연결 안내는 `LOCAL_GIT_SETUP.md`를 따릅니다.

### 완료 시 직접 수행할 절차

1. 기존 Git 상태·HEAD·원격 main·사용자 변경·스테이징 상태를 확인하고 이번 작업 소유 파일을 정합니다. `docs/research/**`는 보호합니다.
2. 변경 범위에 맞는 검증을 실제 실행합니다. 문서 변경은 내용·경로·공유 안전 검사, 스크립트 변경은 구문 및 필요한 실행 테스트, 앱 코드/리소스/빌드 변경은 해당 기능 검사와 정식 Gradle 빌드·Lint·필요한 테스트를 요구합니다. 전체 빌드가 불가능하면 문서만 따로 게시하고 미검증 앱 변경은 보존한 채 제외합니다.
3. `CODEX_PROGRESS.md`에 실제 결과를 기록합니다. 작업 실패/환경 장애도 정확히 쓰며 완료·게시 성공으로 꾸미지 않습니다.
4. diff와 staged diff를 검토하고 이번 작업의 검증된 파일만 `git add -- <명시적 경로...>`로 스테이징합니다. 기존 사용자 변경이 섞인 파일은 작업 부분을 분리할 수 있을 때만 포함합니다. 미완료 변경이 다른 파일에 남아 있다는 이유로 삭제/reset/자동 stash하지 않습니다. 기존 스테이징 변경이 있으면 그것을 포함한 채 commit하지 않습니다.
5. 명확한 메시지로 로컬 커밋을 생성합니다. 이 자동 커밋은 상시 승인 범위입니다. 원격을 fetch하고 원격 main이 커밋의 조상인지 확인한 후 일반 push를 수행합니다. 원격 선행·분기·충돌 시 중단하며 강제 병합/강제 push하지 않습니다.
6. 원격 커밋·파일 해시 또는 내용을 확인합니다. 다른 작업이 원격에 추가되면 보존하고 검증한 커밋이 현재 main의 이력에 포함되는지 확인합니다.
7. 최종 결과에 게시 경로·커밋·검증 범위·미완료를 보고합니다. 새로운 GitHub 업로드 프롬프트는 필요하지 않습니다.

로컬 CLI가 환경 제한으로 막힐 때는 이미 인증된 GitHub 연결 도구를 통한 검증된 파일 게시를 사용할 수 있습니다. 현재 main을 기반으로 이번 파일만 추가/갱신하고 기대 부모/SHA를 대조하여 타인의 변경을 덮어쓰지 않습니다. 자동으로 모든 로컬 파일을 다시 올리지 않습니다. API 게시와 CLI push의 성공 여부는 따로 보고합니다. 로컬 인증을 우회하기 위해 토큰을 추출하거나 평문 파일에 저장하지 않습니다.

## 이전 초기 공유와 선택적 보조 스크립트 기록

아래는 초기 공유/보조 도구의 사용법입니다. 자동 커밋 자체를 금지하는 뜻이 아니며 위의 완료 규칙을 우선합니다.

## 초기 공유와 로컬 Git의 차이

연결된 GitHub 계정/저장소 권한 확인에 성공했습니다. 로컬 Git/gh 실행 파일과 `.git`은 발견되지 않았습니다. 초기 공유는 사용자가 요청한 기존 소스와 문서의 기준 스냅샷이며 GitHub 연결 도구를 사용합니다. 전체 Gradle 빌드·APK 실행·SDK 수신은 미검증임을 보고서에 명시합니다. 이를 검증 완료 앱 배포로 표현하지 않습니다.

GitHub 연결 도구의 인증은 로컬 Windows의 Git 인증을 설정하지 않습니다. 로컬 명령으로 동기화하려면 Git 설치 위치 확인 또는 승인 후 Git for Windows 설치 및 사용자 로그인, 원격 기록을 보존하는 로컬 연결이 필요합니다. 현재 폴더를 삭제하거나 기존 파일 위에 `clone`/`checkout`/`reset --hard`를 실행하지 않습니다. 실제 연결 전 로컬 변경과 원격 내용을 대조합니다.

## 개발 완료 시 공유 절차

1. 변경 내용을 검토하고 필요한 검증을 실제로 실행합니다. 앱 소스/빌드 설정/리소스 변경은 정식 Gradle `:app:assembleDebug`, `:app:lintDebug`, `:app:testDebugUnitTest`를 모두 통과해야 합니다. 문서·스크립트 변경은 해당 변경의 검사와 스크립트 구문 검사 등을 기록합니다.
2. `docs/CODEX_PROGRESS.md`에 완료 작업·수정 파일·검증 결과·오류·미구현·다음 작업과 시간대를 갱신합니다.
3. 파일을 명시적으로 검토·스테이징하고 로컬 커밋합니다. 작업 완료·검증 성공 시 Codex가 이를 자동 수행합니다. 무조건적인 `git add .`나 미완료 변경의 자동 커밋은 사용하지 않습니다. 이 보조 스크립트 자체는 스테이징/커밋을 대신하지 않습니다.
4. 해당 HEAD에서 검증을 확인하고, Git 제외 경로 `.sync/validated-commit.json`에 아래 구조의 완료 기록을 작성합니다. `commit`은 실제 HEAD SHA, `reportSha256`은 `Get-FileHash docs/CODEX_PROGRESS.md -Algorithm SHA256`의 대문자 해시, `checks`는 이 HEAD의 실제 실행 결과입니다. 검사 이름만 채우거나 종료 코드를 꾸며 넣지 않습니다. HEAD가 바뀌면 검증을 다시 해야 합니다.

   ```json
   {
     "commit": "실제로 검증한 HEAD의 40자리 SHA",
     "status": "passed",
     "reportSha256": "진행 보고서의 실제 SHA256",
     "checks": [
       { "name": "assembleDebug", "exitCode": 0 },
       { "name": "lintDebug", "exitCode": 0 },
       { "name": "testDebugUnitTest", "exitCode": 0 }
     ]
   }
   ```

5. 프로젝트 루트에서 `powershell.exe -NoProfile -File .\scripts\Publish-ValidatedCommit.ps1`를 실행합니다. 실행 정책은 임의 변경하지 않습니다.
6. 업로드 후 출력된 커밋과 GitHub의 보고서·파일을 확인합니다. 현재 작업의 업로드 SHA는 다음 진행 보고서에서 참조할 수 있습니다. 보고서 안에 자기 자신의 커밋 SHA를 넣으려는 반복 커밋은 만들지 않습니다.

완료 기록은 검증한 작업을 표시하는 로컬 신뢰 기록이며 테스트 증명의 암호학적 서명이 아닙니다. 개발 담당자가 실제 검증 후에만 생성합니다. 현재는 정식 Gradle 검증이 없으므로 완료 기록을 만들지 않았고 게시 스크립트도 실행하지 않았습니다. 초기 업로드 예외를 향후 자동 동기화에 적용하지 않습니다.

현재 세션에서는 `.ps1` 직접 실행이 PowerShell 정책으로 차단됐습니다. 스크립트의 구문 검사와 별도 인라인 파일 검사는 통과했으나 스크립트 런타임은 미검증입니다. 운영 전 사용자 환경의 실행 정책을 확인해야 하며 정책 변경·우회는 자동으로 수행하지 않습니다.

## 보호 동작과 한계

- 등록된 HTTPS origin의 `main`만 사용하며 인증값이 들어간 URL·추가 push URL은 거부합니다.
- 작업 트리가 변경 중이거나 완료 기록/HEAD/보고서 해시가 일치하지 않으면 중단합니다.
- 추적된 텍스트 파일을 경로·크기·링크·자격증명 패턴으로 검사합니다. 검사로 모든 비밀 탐지가 보장되지는 않으므로 사람이 공유 파일도 검토합니다. 새 바이너리/파일 형식은 자동 게시하지 않습니다.
- 사용자 인증 팝업을 자동으로 띄우지 않습니다. 인증 실패 시 별도 사용자 승인·로그인 후 재시도합니다.
- fetch 후 원격 기록이 로컬 HEAD의 조상인지 확인합니다. 원격이 앞서 있거나 충돌 가능성이 있으면 중단합니다. 강제 push, 자동 pull/merge/rebase, 삭제/reset/stash는 하지 않습니다. 검사 중 원격이 바뀌어도 일반 push가 이력 덮어쓰기를 거부합니다.
- 이 보조 도구는 수정 중인 코드·보고서를 스테이징하거나 커밋하지 않고 이미 검증된 커밋만 전송합니다. Codex의 별도 완료 절차에서는 검증된 명시적 변경 파일만 자동 커밋할 수 있습니다.
- 실패 시 콘솔과 Git 제외 경로 `.sync/publish-errors.log`에 원인 범주를 기록합니다. 원격 오류 원문·토큰은 로그에 복사하지 않습니다. 로컬 로그는 자동 알림이 아니므로 무인 운영 전 오류 확인 방식도 합의해야 합니다.

## 30분 간격 Windows 작업 스케줄러 검토

**등록하지 않았습니다.** Git 설치·로컬 인증·정식 검증·게시 스크립트 실제 성공 확인과 사용자 별도 승인이 먼저 필요합니다.

승인 후 구성 후보:

- 현재 사용자 권한, 로그인한 동안 실행, 관리자 권한 사용 안 함.
- 30분 반복 트리거. 실행 파일은 Windows PowerShell, 인수는 `-NoProfile -NonInteractive -File "C:\Users\kyc66\NextDrive\scripts\Publish-ValidatedCommit.ps1"`.
- 작업 중복 실행은 `IgnoreNew`, 실행 제한 10분, Git 인증은 사전에 사용자 세션에서 완료.
- 변경 작업이 진행 중이면 중단하고 이후 주기에 재확인합니다. 완료 기록이 있는 기존 커밋만 push하므로 30분마다 미완성 코드를 수집하지 않습니다.
- 앱이 닫혀 있어도 Windows 작업은 실행할 수 있으나 Codex의 작업 완료 여부를 자동 판단하지 않습니다. 완료 기록과 실제 검사 결과가 필요합니다.
- 오류 시 작업 결과 코드/로컬 로그 확인이 기본입니다. Windows 알림 등을 추가하려면 별도로 합의하며 메일·외부 메시지는 자동 발송하지 않습니다.

공식 근거: [Git push와 fast-forward 보호](https://git-scm.com/docs/git-push), [Windows 반복 작업 트리거](https://learn.microsoft.com/en-us/powershell/module/scheduledtasks/new-scheduledtasktrigger).
